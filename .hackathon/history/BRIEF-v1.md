## What judges will reward (plain words)
1. **Technical Implementation 25% + Functionality & Prototype 20% = 45% on the build.** Judges will read the code and watch it run, so a demo made of mocks will lose marks here. Pick a problem where one core journey can be built for real in about 18 hours, with real backend, real data flow and real AI/logic, then polish that journey.
2. **Innovation 20%.** Using a different model doesn't count. Look for an angle on the problem that other teams won't find. Expect most teams to build the obvious idea, so look for the smarter one.
3. **Problem Relevance & Impact 20%.** Choose a problem with a real, named user and sourced numbers. The PPT must also cover real-world use, impact, limitations and future work.

What this means for picking: avoid ideas that only look good on slides. Favour a problem where the hard part is something the team can actually code (M3's AI and core logic, M1's backend) and show working end to end.
