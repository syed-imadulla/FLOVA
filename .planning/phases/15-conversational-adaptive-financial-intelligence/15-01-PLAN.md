# Plan 15-01: Conversational & Adaptive Financial Intelligence

## Phase: 15-conversational-adaptive-financial-intelligence
## Owner: M1 Backend & Integration

---

## 1. Overview & Objectives
Transform FLOVA into an adaptive, conversational financial companion by implementing:
1. Multi-transaction conversational voice capture and batch arithmetic (integer paise, zero LLM math).
2. Read-only Invoice Intelligence Agent with receivables/payables tracking and partial settlements.
3. Smart expense intelligence, adaptive safety buffer engine, income forecasting, and hypothetical scenario simulator.
4. WISH 2.0 persistent database savings goals with non-coercive milestone celebrations and safe localStorage migration.
5. Grounded Voice Financial Assistant answering natural financial queries using live engine data.
6. Full database migrations, RLS policies, automated regression suites, and production build verification.

---

## 2. Work Breakdown & Execution Waves

### Wave 1: Database Migrations & Data Contracts
- **1.1 Migration `backend/supabase/migrations/20261121000400_invoices_and_wish.sql`:**
  - Create table `invoices`: `id UUID PRIMARY KEY`, `user_id UUID REFERENCES auth.users`, `direction TEXT CHECK (direction IN ('receivable', 'payable'))`, `supplier_name TEXT`, `customer_name TEXT`, `invoice_number TEXT`, `invoice_date DATE`, `due_date DATE`, `total_amount NUMERIC(12,2) NOT NULL CHECK (total_amount > 0 AND total_amount <= 1000000)`, `paid_amount NUMERIC(12,2) NOT NULL DEFAULT 0.00`, `status TEXT CHECK (status IN ('uploaded', 'unpaid', 'partially_paid', 'paid', 'overdue', 'cancelled'))`, `file_path TEXT`, `metadata JSONB`, `created_at TIMESTAMPTZ`, `updated_at TIMESTAMPTZ`.
  - Create table `invoice_items`: `id UUID PRIMARY KEY`, `invoice_id UUID REFERENCES invoices ON DELETE CASCADE`, `name TEXT NOT NULL`, `quantity NUMERIC(10,2)`, `unit_price NUMERIC(12,2)`, `amount NUMERIC(12,2) NOT NULL`.
  - Create table `invoice_settlements`: `id UUID PRIMARY KEY`, `invoice_id UUID REFERENCES invoices ON DELETE CASCADE`, `amount NUMERIC(12,2) NOT NULL CHECK (amount > 0)`, `settled_at DATE NOT NULL`, `transaction_id UUID REFERENCES transactions`, `payout_id UUID REFERENCES payouts`, `notes TEXT`.
  - Create table `wish_goals`: `id UUID PRIMARY KEY`, `user_id UUID REFERENCES auth.users`, `title TEXT NOT NULL`, `target_amount NUMERIC(12,2) NOT NULL CHECK (target_amount > 0)`, `saved_amount NUMERIC(12,2) NOT NULL DEFAULT 0.00`, `target_date DATE`, `icon TEXT`, `status TEXT DEFAULT 'active'`, `created_at TIMESTAMPTZ`, `updated_at TIMESTAMPTZ`.
  - Create table `wish_contributions`: `id UUID PRIMARY KEY`, `goal_id UUID REFERENCES wish_goals ON DELETE CASCADE`, `amount NUMERIC(12,2) NOT NULL CHECK (amount > 0)`, `contributed_at DATE NOT NULL`, `notes TEXT`.
  - RLS policies on all new tables: User can SELECT, INSERT, UPDATE, DELETE only rows where `user_id = auth.uid()` or via parent ownership.
- **1.2 Contracts (`frontend/src/types/contracts.ts`):**
  - Add `Invoice`, `InvoiceItem`, `InvoiceSettlement`, `WishGoal`, `WishContribution` interfaces.
  - Extend `VoiceTransactionCandidate` with batch metadata, multi-utterance session context, and conversational correction markers.

### Wave 2: Deterministic Intelligence Engines (M3 Integration)
- **2.1 Batch Arithmetic Engine (`frontend/src/engine/batchArithmetic.ts`):**
  - Given an array of candidates, deterministically calculate: total income (paise), total expenses (paise), net movement (paise), category breakdowns, and validation status.
  - LLM math is strictly forbidden; all sums and balances computed in integer paise.
- **2.2 Adaptive Safety Buffer Engine (`frontend/src/engine/adaptiveBuffer.ts`):**
  - Calculate recommended buffer: `Daily Essential Cost (living + work) × Horizon Days + Upcoming Obligations`.
  - Adapts protection horizon based on profile: daily earners (2-3 days), weekly (7 days), freelancers/variable (14-21 days).
  - Pure planning boundary: explained transparently; never deducted silently from confirmed balance.
- **2.3 Income Forecasting Engine (`frontend/src/engine/incomeForecast.ts`):**
  - Statistical/deterministic projection using historical income transactions, payout frequency, and variability.
  - Shows lower/upper confidence bounds and explicitly flags "Insufficient Data" when history is sparse.
- **2.4 Financial Scenario Simulator (`frontend/src/engine/scenarioSimulator.ts`):**
  - Evaluates "What-If" scenarios (e.g. ±X% income, delayed payout by N days, ±₹Y daily spending, unexpected ₹Z expense).
  - Re-runs runway calculations without modifying any real database transactions or check-ins.
- **2.5 Smart Expense Intelligence (`frontend/src/engine/spendingIntelligence.ts`):**
  - Evaluates category distributions, week-over-week variance, work vs personal splits, and spending velocity.

### Wave 3: Invoice Intelligence & Voice Session Services
- **3.1 Invoice Service (`frontend/src/services/invoices.ts`):**
  - Ingestion, listing, filtering, and partial settlement of invoices.
  - Integration: Confirmed receivable can link to an expected payout; confirmed payable can link to a commitment.
  - Prevents double-counting by strictly updating `paid_amount` and deriving outstanding amounts.
- **3.2 Multi-Transaction & Conversational Voice Service (`frontend/src/services/voice.ts`):**
  - Upgrade `processVoice` and prompt in `backend/supabase/functions/process-voice/index.ts` to output array of candidates for multi-clause utterances.
  - Handle conversational corrections ("Change the petrol expense to ₹250", "Remove the groceries item").
  - Maintain session draft state in memory before final confirmation.
