# Plan 08-01: Secure FLOVA Catch (Receipt Extraction)

## Objectives
Build an end-to-end receipt extraction flow that uses Groq via a secure Supabase Edge Function (`extract-receipt`), outputs truthful `ExtractedReceiptCandidate` suggestions without fabricating financial figures, provides an interactive review/edit UI, and persists confirmed expenses using `confirmCandidateTransaction()`.

## Edge Function Contract (`extract-receipt`)
- **Endpoint**: `POST /functions/v1/extract-receipt`
- **Headers**:
  - `Authorization: Bearer <user_jwt>` (required; authenticated user check)
  - `Content-Type: application/json`
- **Request Body**:
  ```json
  {
    "imageBase64": "data:image/jpeg;base64,...", // Optional if text is provided
    "mimeType": "image/jpeg",
    "text": "Indian Oil Petrol Pump Total: Rs 250.00 Date: 2026-11-20" // Optional if image is provided
  }
  ```
- **Response Body**:
  ```json
  {
    "candidate": {
      "id": "client-uuid",
      "merchant": "Indian Oil",
      "amountPaise": 25000,
      "category": "fuel",
      "expenseType": "work",
      "date": "2026-11-20",
      "description": "Petrol refill",
      "confidence": 0.95,
      "needsReview": false,
      "missingFields": []
    },
    "rawText": "..."
  }
  ```
- **Error Responses**:
  - `400 Bad Request`: Neither image nor text provided.
  - `401 Unauthorized`: Missing or invalid Supabase Auth JWT.
  - `502 Bad Gateway`: Upstream Groq API failure or timeout.

## Security Boundaries & Rules
1. **Zero Client Secrets**: `GROQ_API_KEY` is never referenced in `frontend/src/` or exposed to Vite client bundles. Only accessed in `Deno.env.get("GROQ_API_KEY")` inside the Supabase Edge Function (`extract-receipt`).
2. **Authenticated Access**: The Edge Function validates the caller's JWT using `supabase.auth.getUser(token)`.
3. **No Automatic Database Mutations**: Extraction is strictly read-only inference. It NEVER inserts, updates, or deletes financial transactions.
4. **Contract Alignment**: Uses `description`, not `notes`. Supports nullable `amountPaise`, `merchant`, `category`, and `date`.
5. **Contextual Dates**: Does not automatically reject future dates without considering receipt context.
6. **Confidence Estimate**: `confidence` represents model extraction clarity, not payment proof.
7. **User Confirmation**: Only explicit user confirmation invokes `confirmCandidateTransaction()`, preserving client UUID for idempotency and adhering to database RLS.

## Implementation Tasks

### Task 0: Supabase Edge Function (`backend/supabase/functions/extract-receipt/index.ts`)
- Implement CORS headers and preflight handling.
- Authenticate request with Supabase Auth token via `supabase.auth.getUser()`.
- Validate payload: requires either valid image or text.
- Invoke Groq API (`https://api.groq.com/openai/v1/chat/completions`):
  - Model: `llama-3.2-11b-vision-preview` (for image) or `llama-3.3-70b-versatile` (for text).
  - System instructions: Extract merchant, amount (rupees), date, category, expense_type (living/work/null), and description. Strictly forbid guessing or hallucinating missing numbers.
  - JSON Mode: `response_format: { type: "json_object" }`.
- Parse response, validate integer paise (`Math.round(amount * 100)`), flag `needsReview` when fields are missing or ambiguous, and return `ExtractedReceiptCandidate`.

### Task 1: Frontend Receipt Service (`frontend/src/services/receipt.ts`)
- Add `extractReceipt(input: { file?: File; text?: string }): Promise<ExtractedReceiptCandidate>`
- Convert image `File` to base64 Data URL with size validation (< 5MB).
- Call `supabase.functions.invoke("extract-receipt", { body: ... })`.
- Assign client-side UUID (`crypto.randomUUID()`) to the candidate for idempotency.
- Return structured `ExtractedReceiptCandidate`.

### Task 2: FLOVA Catch UI (`frontend/src/pages/FlovaCatchPage.tsx` & Route)
- Create `/catch` route wrapped with `RequireAuth` and `RequireOnboarded`.
- Upload & input section:
  - Image upload with camera capture option (`accept="image/*"`).
  - Pasted text fallback textarea (for SMS / WhatsApp bills).
  - "Extract Details" action with loading feedback.
- Candidate Review & Edit Section:
  - Displays thumbnail/text preview.
  - Editable form prefilled with candidate values (Merchant, Amount in ₹, Date, Category, Living/Work, Description).
  - Missing field alert banner (e.g. "Amount was not detected", "Select Living or Work").
  - "Confirm & Save" button: validates inputs and calls `confirmCandidateTransaction(editedCandidate)`.
  - "Discard" button: clears state without saving.
  - Success banner with direct link to view transaction in Activity history.

### Task 3: Automated Test Suite (`frontend/src/services/__tests__/receiptExtraction.test.ts`)
Implement automated tests verifying:
1. Valid receipt extraction (converts amount ₹120.00 to 12,000 paise, maps merchant, category, and description).
2. Missing amount receipt (sets `amountPaise: null`, `needsReview: true`, `missingFields: ["amount"]`).
3. Unreadable receipt (handles low confidence, retains null fields, avoids hallucinated values).
4. Invalid amount / date validation (rejects negative numbers, formats cleanly).
5. Uncertain extraction handling (requires user review when multiple totals or ambiguous categories exist).
6. User edits candidate before confirmation (modified merchant, amount, or expenseType correctly saved).
7. User rejects candidate (state discarded, zero database rows created).
8. Duplicate submission idempotency (UUID preserved across retry calls).
9. Edge Function / Groq API error handling (graceful failure reporting, retry option).
