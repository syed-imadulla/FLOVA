# Plan 14-01: Smart Capture, Receipt Intelligence & UPI Share Integration

## Phase: 14-smart-capture-receipt-intelligence-upi-share-integration
## Owner: M1 Backend & Integration

---

## 1. Plan Overview
Implement complete multi-source capture architecture for FLOVA:
- Physical receipts with line items, tax, discounts, and strict date fallback logic.
- UPI payment screenshots with payment status detection (`successful`, `pending`, `failed`, `unknown`), 12-digit UTR/UPI reference extraction, and duplicate detection.
- Mobile camera vs gallery picker separation in `CatchScreen.tsx`.
- PWA Web Share Target API in `manifest.webmanifest` and Service Worker `sw.js`.
- Unified `/add` confirmation flow with status warnings, duplicate alerts, and candidate stability.
- Dedicated regression test suite covering all 6 capture sources and edge cases.

---

## 2. Work Breakdown

### Wave 1: Schema, Contracts, Edge Function & Service Contracts
- **1.1 Contract Extension (`frontend/src/types/contracts.ts`):**
  - Add fields to `ExtractedReceiptCandidate`:
    - `kind?: 'physical_receipt' | 'upi_screenshot' | 'payment_sms' | 'unknown'`
    - `paymentStatus?: 'successful' | 'pending' | 'failed' | 'unknown'`
    - `upiReference?: string | null`
    - `upiApp?: string | null`
    - `items?: Array<{ name: string; quantity?: number; price?: number }>`
    - `subtotalPaise?: number | null`
    - `taxPaise?: number | null`
    - `discountPaise?: number | null`
    - `extractedDate?: string | null`
    - `scannedAt?: string`
    - `dateFallback?: boolean`
    - `possibleTotals?: number[]`
    - `duplicateWarning?: { existingTransactionId: string; reference: string } | null`
- **1.2 Edge Function Update (`backend/supabase/functions/extract-receipt/index.ts`):**
  - Update system prompt to recognize physical receipts, UPI screenshots (Google Pay, PhonePe, Paytm, CRED, BHIM), and payment SMS text.
  - Extract detailed fields (merchant, amount, items, taxes, payment status, UTR / UPI reference ID, app name).
  - Enforce date fallback: if date is present on receipt, return it; otherwise return null (do NOT hallucinate date).
  - Enforce anti-hallucination rules (distinguish invoice numbers, GST numbers, phone numbers from total amounts).
- **1.3 Receipt Service (`frontend/src/services/receipt.ts`):**
  - Pass file/text to `extract-receipt` function.
  - Implement client-side fallback parsing when offline for both receipts and UPI text.
  - Implement duplicate reference checker against existing transactions (`checkDuplicateUpiReference(upiReference)`).

### Wave 2: PWA Share Target & Service Worker
- **2.1 `frontend/public/manifest.webmanifest`:**
  - Add `share_target` configuration for POST `/share-target` supporting text, url, and image files (`media`).
- **2.2 `frontend/public/sw.js`:**
  - Add event listener to intercept POST requests to `/share-target`.
  - Store incoming files/text into Cache / temporary store.
  - Redirect client window to `/catch?shared=1`.
- **2.3 Share Ingestion in `frontend/src/screens/CatchScreen.tsx`:**
  - Check for shared content on mount (via URL query parameters or temporary cache).
  - Automatically load shared image or populate shared text.

### Wave 3: UI Enhancement in `CatchScreen.tsx` & `AddScreen.tsx`
- **3.1 `CatchScreen.tsx`:**
  - Add dual input options: "Take Photo" (opens camera) and "Choose from Gallery" (opens phone gallery).
  - Show image preview with remove, change, and retake actions.
  - Display progress indicator ("Reading receipt / screenshot...").
  - Add support for UPI screenshots with guidance text.
  - Handle shared UPI content automatically.
- **3.2 `AddScreen.tsx` & `TransactionForm.tsx`:**
  - Display extraction metadata banner:
    - Receipt details (merchant, date fallback notification, line items count).
    - UPI screenshot details (payment app, UTR reference).
    - Status warning: if payment status is `pending` or `failed`, display high-contrast alert preventing accidental confirmation of unearned/unpaid amounts.
    - Duplicate warning: if transaction reference matches an existing record, alert user with existing transaction link.

### Wave 4: Test Verification & Audit
- **4.1 Dedicated Regression Suite (`frontend/src/services/__tests__/smartCaptureReceiptUpi.test.ts`):**
  - Receipt tests: date fallback, line items, taxes/discounts, multiple totals disambiguation.
  - UPI screenshot tests: successful, pending, failed, unknown status handling.
  - Duplicate reference detection.
  - Camera vs gallery input mode checks.
  - Share target manifest and parsing checks.
  - Financial limit & candidate stability preservation.
- **4.2 End-to-End Build & Live Verification:**
  - Engine tests, db tests, frontend build, browser audit.
