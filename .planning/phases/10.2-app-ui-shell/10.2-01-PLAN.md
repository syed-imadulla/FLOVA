# Phase 10.2: Application UI shell and screens — Plan 01

## Goal
A stable, mobile-first PWA in the existing React 18 + Vite app. Every authenticated screen sits in one persistent layout with a bottom navbar (Home · Activity · Mic · Insights · More), and each screen reads and writes through the existing services and hooks. No new backend.

## Decisions
- Stack stays React + Vite PWA. React Native was ruled out on 2026-11-21 because it can't deliver a PWA and would mean a rewrite.
- The language chips set the voice-input language only (en, hi, kn, ur, te). Full UI translation is deferred.
- One persistent layout route, so the nav never remounts between screens.
- AI only suggests. Every voice or receipt result goes through an editable review, and nothing saves without Confirm. A missing amount, or a missing living/work classification for own expenses, blocks saving.
- After every mutation the screen calls `useDataVersion().bump()`, so the runway and dashboard refresh.

## Tasks
1. UI kit in `src/ui/`: tokens, icons, Screen header, Card, Button, MoneyInput, Segmented, Sheet, Skeleton, Notice, EmptyState.
2. `AppLayout`: persistent bottom nav, safe-area insets, centred 480px column on desktop, scroll reset on navigation.
3. Screens in `src/screens/`: Home, Check-in, Voice (+ review for transaction, payout, check-in and query), Scan receipt, Add, Activity, Insights (Runway | Insights), Wish, More, Payouts, Commitments, Profile.
4. Route consolidation in `App.tsx`. Legacy URLs redirect, and the replaced pages are removed so no screen exists twice.
5. Expose the buffer, spendable balance and buffer-shortfall date from `runway/adapter.ts` (additive).
6. Verify: existing suites, `npm run build`, and the browser at 375px.

## Out of scope
Full UI translation, server-side Wish storage (it stays in localStorage), new AI features, deployment.
