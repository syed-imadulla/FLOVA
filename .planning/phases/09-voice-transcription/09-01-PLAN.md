# Plan 09-01: Secure Voice Transcription and Financial Intent Integration

## Objectives
Build an end-to-end voice transcription and financial intent extraction flow that captures spoken audio or typed text, transcribes audio via Groq Whisper (`whisper-large-v3-turbo`), parses financial intent via Groq Llama 3.3 (`llama-3.3-70b-versatile`) into `FinancialExtractionDTO` and `VoiceTransactionCandidate`, provides an interactive M2 review interface with deterministic financial query handling, and persists confirmed transactions via `confirmCandidateTransaction()`.

## Edge Function Contract (`process-voice`)
- **Endpoint**: `POST /functions/v1/process-voice`
- **Headers**:
  - `Authorization: Bearer <user_jwt>` (required; authenticated caller check)
  - `Content-Type: application/json`
- **Request Body**:
  ```json
  {
    "audioBase64": "data:audio/webm;base64,...", // Optional if text is provided
    "mimeType": "audio/webm",
    "text": "Spent 120 rupees on petrol for delivery" // Optional if audio is provided (text fallback)
  }
  ```
- **Response Body**:
  ```json
  {
    "extraction": {
      "intent": "record_transaction",
      "transcript": "Spent 120 rupees on petrol for delivery",
      "confidence": 0.96,
      "needsReview": false,
      "missingFields": [],
      "transaction": {
        "type": "expense",
        "amountPaise": 12000,
        "category": "fuel",
        "expenseType": "work",
        "date": "2026-11-20",
        "ownership": "mine",
        "description": "Spent 120 rupees on petrol for delivery"
      }
    },
    "candidate": {
      "id": "client-uuid",
      "transcript": "Spent 120 rupees on petrol for delivery",
      "type": "expense",
      "amountPaise": 12000,
      "category": "fuel",
      "expenseType": "work",
      "date": "2026-11-20",
      "ownership": "mine",
      "confidence": 0.96,
      "needsReview": false,
      "missingFields": []
    }
  }
  ```
- **Error Responses**:
  - `400 Bad Request`: Neither audio nor text provided.
  - `401 Unauthorized`: Missing or invalid Supabase Auth JWT.
  - `500 Server Error`: `GROQ_API_KEY` not configured.
  - `502 Bad Gateway`: Upstream Groq Whisper or LLM failure.

## Security Boundaries & Guardrails
1. **Zero Client Secrets**: `GROQ_API_KEY` is accessed strictly in `Deno.env.get("GROQ_API_KEY")` inside the Supabase Edge Function (`process-voice`). Never in frontend client code.
2. **Authenticated Access**: The Edge Function validates the caller's JWT using `supabase.auth.getUser(token)`.
3. **No Automatic Database Mutations**: Voice processing is strictly read-only. It NEVER inserts, updates, or deletes financial records in the database.
4. **Canonical DTOs**: Preserves `FinancialExtractionDTO` and `VoiceTransactionCandidate`.
5. **Truthful Uncertainty**: Missing amounts, dates, and classifications remain `null`, `needsReview: true`, with missing fields listed. Never invents financial data.
6. **Mandatory User Confirmation**: Only explicit user click on "Confirm & Save" invokes `confirmCandidateTransaction()`, preserving client UUID for idempotency and adhering to database RLS.

## Team Coordination Roles
- **M1 (Backend & Integration)**: Edge Function `process-voice`, server-side Groq integration, auth validation, `confirmCandidateTransaction()` persistence, and automated regression tests.
- **M2 (UI & Review)**: Voice interaction screen (`/voice`), microphone interaction states, review/edit form, missing fields warnings, and query answer card.
- **M3 (Engine & Intent)**: Validation of `FinancialExtractionDTO` and answering financial queries using the deterministic runway engine.
- **M4 (Audio & Voice Capture)**: Web Audio `MediaRecorder` hook, permissions handling, base64 encoding, and audio timer.

## Implementation Tasks

### Task 0: Contracts Extension (`frontend/src/types/contracts.ts`)
- Export `VoiceIntentType`: `"record_transaction" | "financial_query" | "unknown"`.
- Export `FinancialQueryType`: `"runway_check" | "balance_check" | "payout_check" | "general"`.
- Export `FinancialExtractionDTO` mirroring the canonical shape.

### Task 1: Supabase Edge Function (`backend/supabase/functions/process-voice/index.ts`)
- Implement CORS headers and preflight handling.
- Authenticate request with Supabase Auth token via `supabase.auth.getUser()`.
- Validate payload: requires either valid audio or text.
- If audio provided: invoke Groq Whisper API (`https://api.groq.com/openai/v1/audio/transcriptions` with `model: "whisper-large-v3-turbo"`).
- Invoke Groq Llama 3.3 (`llama-3.3-70b-versatile` with JSON mode) to classify intent and extract transaction or query fields.
- Anti-hallucination prompt: strictly forbid inventing missing amounts or dates.
- Parse response, validate integer paise (`Math.round(amount_rupees * 100)`), flag `needsReview` when fields are missing, and return `{ extraction, candidate }`.

### Task 2: Frontend Voice Service & Audio Capture Hook
- `frontend/src/services/voice.ts`:
  - `processVoice(input: { audioBlob?: Blob; text?: string }): Promise<{ extraction: FinancialExtractionDTO; candidate: VoiceTransactionCandidate | null }>`
  - Blob to base64 Data URL converter.
  - Client UUID assignment for candidate idempotency.
- `frontend/src/hooks/useVoiceRecorder.ts`:
  - `navigator.mediaDevices.getUserMedia` wrapper with audio stream cleanup.
  - Records chunks into `Blob` with MIME type `audio/webm;codecs=opus` (or fallback).
  - Provides recording timer and error handling.

### Task 3: Voice UI Page (`frontend/src/pages/VoicePage.tsx` & Route)
- Create `/voice` route wrapped with `RequireAuth` and `RequireOnboarded`.
- Microphone recording component:
  - Big circular microphone button with active recording pulse animation.
  - Recording duration timer ("00:04", "00:05").
  - "Stop & Process" and "Cancel" controls.
  - Pasted / typed text fallback input for noisy environments.
- Candidate Review & Edit Section (when `intent === "record_transaction"`):
  - Pre-fills detected values (Type, Amount in ₹, Category, Living/Work, Date, Transcript as description).
  - Missing field alert banner when `needsReview` is true.
  - Living vs Work toggle (required for expenses).
  - "Confirm & Save" button: calls `confirmCandidateTransaction()`.
  - "Discard" button: clears state without saving.
- Financial Query Answer Section (when `intent === "financial_query"`):
  - Resolves query against `useRunway()` and confirmed balances.
  - Displays factual answers (e.g. Confirmed liquid balance ₹3,930; Saturday rent shortfall ₹1,170).

### Task 4: Automated Test Suite (`frontend/src/services/__tests__/voiceIntent.test.ts`)
Implement automated tests verifying:
1. Income intent extraction ("Received 500 rupees tip from customer" -> `type: "income"`, `amountPaise: 50000`, `category: "tips"`).
2. Work expense extraction ("Spent 120 rupees on petrol for delivery" -> `type: "expense"`, `expenseType: "work"`, `amountPaise: 12000`).
3. Living expense extraction ("Spent 40 rupees on tea and snack" -> `type: "expense"`, `expenseType: "living"`, `amountPaise: 4000`).
4. Missing amount voice extraction ("Filled petrol at pump" -> `amountPaise: null`, `needsReview: true`, `missingFields: ["amount"]`).
5. Missing expenseType extraction (blocks confirmation without user selecting living vs work).
6. Financial query intent ("How much money do I have left?" -> `intent: "financial_query"`, `queryType: "balance_check"`).
7. Read-only extraction guarantee (0 transaction rows created before confirmation).
8. User rejection (discarding clears candidate with 0 rows created).
9. Duplicate submission idempotency (UUID preserved across retry calls).
10. Edge Function / Groq API error handling (graceful failure reporting).
