# Plan 10-01: Financial Activity, Money Overview & Deterministic Insights

## Phase: 10
## Plan: 01
## Owner: M1 (Backend/Contracts) & M2/M3 (Frontend & Insights Engine)

## Objective
Connect Financial Activity (`/activity`) and Money Overview (`/overview`) to authenticated Supabase data services and the deterministic M3 financial engine, surface four explainable insights, and ensure full manual usability.

## Tasks

### 1. Extend Contracts & Timeline Service
- In `frontend/src/types/contracts.ts`:
  - Extend `ActivityItemKind` to include `"expected_payout"`.
  - Extend `ActivityItem` fields to support scheduled payout metadata (expected date, source, status).
- In `frontend/src/services/data.ts`:
  - Extend `listActivityTimeline()` to query `payouts` table for scheduled/unearned records and map them to `kind: "expected_payout"`.
  - Ensure strict chronological descending sort combining transactions, check-ins, and scheduled payouts.

### 2. Implement Deterministic Financial Insights Engine
- Create `frontend/src/engine/insights.ts`:
  - Pure TypeScript, 100% deterministic (zero external AI / LLM dependencies).
  - Evaluates:
    1. `budget_burn`: Today's spending compared against daily living & work estimates.
    2. `shortfall_warning`: Forecasts shortfall date & amount from `ProcessedRunway`.
    3. `payout_coverage`: Matches scheduled payouts against commitments with due dates.
    4. `cod_liability`: Identifies custodial cash held that must not be spent.
  - Returns structured `FinancialInsight[]` array with title, message, severity (`info` | `warning` | `urgent`), and action link.

### 3. Build Financial Activity Screen (`/activity`)
- Create `frontend/src/pages/ActivityPage.tsx`:
  - Reuses `listActivityTimeline()`.
  - Clear filtering controls:
    - Date range: All, Today, Last 7 Days, Last 30 Days.
    - Type filter: All, Income, Living Expense, Work Expense, Check-in, Expected Payout.
    - Category filter: All, Fuel, Food, Phone, Maintenance, Rent, etc.
  - Distinguishes personal funds from third-party / COD funds (`ownership === "not_mine"`).
  - Explicit badges for living vs work expenses.
  - Check-in cards showing cash/bank/total snapshot without adding to income or expenses.
  - Scheduled payout cards showing expected arrival without adding to income.
  - Loading skeleton, clean empty states, and retryable error handling.

### 4. Build Money Overview Screen (`/overview`)
- Create `frontend/src/pages/MoneyOverviewPage.tsx`:
  - Uses `useRunway()` and M3 engine feed.
  - Displays the 10 required financial pillars:
    1. Confirmed liquid available balance (`confirmedBalancePaise`).
    2. Cash and bank balance breakdown.
    3. Own income total.
    4. Own living expenses total.
    5. Own work expenses total.
    6. Custodial COD funds held (clearly segregated with warning: "Platform money, not personal income").
    7. Expected payouts total (segregated as scheduled).
    8. Financial commitments (upcoming bills/rent).
    9. Daily living and work budgets (with remaining today budget indicator).
    10. Estimated runway in days and exact shortfall date/amount.
  - Surfaces the 4 deterministic insights cards generated by `insights.ts`.
  - Quick action buttons: Voice Entry (`/voice`), FLOVA Catch (`/catch`), Manual Entry (`/add`), Check-in (`/checkin`), Full Activity (`/activity`).

### 5. Wire App Routes & Launcher
- In `frontend/src/App.tsx`:
  - Register `/overview` -> `<MoneyOverviewPage />` (guarded by `RequireAuth` & `RequireOnboarded`).
  - Register `/activity` -> `<ActivityPage />` (guarded).
  - Alias `/history` -> `<ActivityPage />`.
- In `frontend/src/pages/HomePlaceholder.tsx`:
  - Promote `/overview` and `/activity` in navigation.

### 6. Automated Verification & Regression Testing
- Create `frontend/src/services/__tests__/activityAndOverview.test.ts`:
  - Test 1: `listActivityTimeline()` loads transactions, check-ins, and expected payouts in unified descending order.
  - Test 2: Check-ins are segregated with `type: "checkin"` and do not mutate income or expense totals.
  - Test 3: Scheduled payouts have `kind: "expected_payout"` with zero income balance impact.
  - Test 4: Living expenses (`expense_type: "living"`) vs work expenses (`expense_type: "work"`) are distinguished.
  - Test 5: Third-party funds (`ownership: "not_mine"`) are flagged as custodial.
  - Test 6: Insights engine produces Budget Burn alert when Day 0 spend > estimate.
  - Test 7: Insights engine produces Shortfall warning matching Saturday −₹1,170 shortfall in Ravi fixture.
  - Test 8: Insights engine detects Payout-Commitment coverage.
  - Test 9: Insights engine generates COD liability notice when custodial cash > 0.
  - Test 10: Missing check-in baseline produces INSUFFICIENT_INFORMATION state truthfully without fabricating 0.
- Run complete test suite and verify 0 regressions.
- Run TypeScript build (`npm run build`).
