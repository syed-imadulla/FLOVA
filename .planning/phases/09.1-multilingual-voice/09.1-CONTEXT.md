# Phase 9.1 Context: Multilingual Voice Support & Language-Specific Financial Extraction

## Goal
Extend FLOVA's voice capture and intent engine to support English (`en`), Hindi (`hi`), Kannada (`kn`), Urdu (`ur`), and Telugu (`te`), alongside default auto-detection (`auto`), ensuring delivery and gig workers across India can record expenses, check-ins, platform payouts, and financial queries in their native language and script.

## Core Requirements & Boundaries
1. **Model Stack**:
   - Audio Transcription: Groq Whisper (`whisper-large-v3-turbo`) with ISO 639-1 language routing.
   - Financial Intent Extraction: Groq Llama 3.3 (`llama-3.3-70b-versatile`) with multilingual Indic prompt tuning.
   - Zero Gemini, OpenAI, or unapproved AI dependencies.
2. **Security & Secrets**:
   - `GROQ_API_KEY` stays strictly server-side in Supabase Edge Function secrets. Zero API keys in frontend bundles.
   - User JWT authentication verified on every edge invocation.
3. **Data Contracts**:
   - Reuses canonical `FinancialExtractionDTO` and `VoiceTransactionCandidate`.
   - Never converts expected payouts or balance check-ins into ordinary income/expense transactions.
   - Enforces truthful uncertainty: missing amount, missing date, or missing expense type remains `null` with `needsReview: true` and clarification questions.
   - Replaces 0 DB rows during extraction: confirmation-before-save is strictly mandatory.
4. **Local Fallback**:
   - When offline or Edge Function unavailable, client-side pattern matcher parses natural language across English, Hindi (Devanagari & Hinglish), Kannada (Kannada script & Kanglish), Urdu (Urdu script & romanized Urdu), and Telugu (Telugu script & romanized Telugu).
