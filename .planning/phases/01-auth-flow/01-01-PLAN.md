## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client Browser → Supabase Auth API | User credentials (email/password) cross public network via TLS to Supabase GoTrue |
| Client React State → Client Router | Session token validity determines access to protected route rendering |
| Supabase Auth → PostgreSQL RLS | JWT claims (sub / auth.uid()) enforce database isolation across all tables |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Spoofing | frontend/src/auth/RequireAuth.tsx | High | mitigate | Validate session presence via AuthProvider reactive listener; unauthenticated states redirect to /login immediately without flashing protected UI |
| T-01-02 | Tampering | backend/supabase/migrations/20261120000200_explicit_grants.sql | High | mitigate | Explicitly revoke all table permissions from anon and restrict table grants to authenticated with RLS policies enforcing auth.uid() |
| T-01-03 | Information Disclosure | frontend/src/pages/auth/LoginPage.tsx | Medium | mitigate | Display sanitized error messages (err.message) in role="alert" without exposing internal stack traces or database connection details |
| T-01-04 | Elevation of Privilege | backend/scripts/test-db.mjs | High | mitigate | Remove test-harness blanket grant on public tables to verify that migration grants alone authorize table access under RLS |
