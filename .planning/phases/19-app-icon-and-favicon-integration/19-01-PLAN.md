# Plan 19-01: FLOVA App Icon and Favicon Generation & Integration

## Phase Overview
- **Phase:** 19 (App Icon and Favicon Integration)
- **Goal:** Transform the master FLOVA brand asset into the complete suite of web favicons, touch icons, and PWA application icons, then integrate and verify them across HTML, Web App Manifest, Service Worker, and production builds.
- **Estimated Duration:** 15 minutes
- **Dependencies:** None (Assets derived strictly from supplied master PNG)

---

## Tasks

### Task 1: Deterministic Icon & Favicon Asset Generation
- **Source:** Master transparent-corner 1024 × 1024 PNG (`media_1795406442151_fd944c97.png`).
- **Steps:**
  1. Copy master PNG to `frontend/public/app-icon-1024.png` preserving exact uncompressed data.
  2. Extract the transparent logo (leaf + rupee core + ribbon) isolated from the external card background to ensure clean rendering on dark/light browser tabs.
  3. Generate `apple-touch-icon.png` (180 × 180) from the app-icon composition using high-fidelity Lanczos resampling.
  4. Generate `icon-192.png` (192 × 192) and `icon-512.png` (512 × 512) for PWA installation.
  5. Generate transparent favicon PNGs:
     - `favicon-16x16.png` (16 × 16)
     - `favicon-32x32.png` (32 × 32)
     - `favicon-48x48.png` (48 × 48)
  6. Generate multi-resolution `favicon.ico` containing 16x16, 32x32, and 48x48 layers.
  7. Generate `favicon.svg` with transparent background preserving exact logo geometry, color gradients, and rupee symbol.
- **Verification:** Run automated Python verification script to assert dimensions, alpha transparency, and file existence for all 8 assets.

### Task 2: PWA & Document Head Integration
- **Steps:**
  1. Update `frontend/index.html`:
     - Set `<link rel="icon" type="image/svg+xml" href="/favicon.svg" />`
     - Set `<link rel="alternate icon" href="/favicon.ico" />`
     - Set `<link rel="icon" type="image/png" sizes="32x32" href="/favicon-32x32.png" />`
     - Set `<link rel="icon" type="image/png" sizes="16x16" href="/favicon-16x16.png" />`
     - Set `<link rel="apple-touch-icon" sizes="180x180" href="/apple-touch-icon.png" />`
     - Ensure `<link rel="manifest" href="/manifest.webmanifest" />` is intact.
  2. Update `frontend/public/manifest.webmanifest`:
     - Register `icon-192.png` (sizes: "192x192", type: "image/png", purpose: "any")
     - Register `icon-512.png` (sizes: "512x512", type: "image/png", purpose: "any")
     - Register `icon-512.png` (sizes: "512x512", type: "image/png", purpose: "maskable")
     - Register `favicon.svg` (sizes: "any", type: "image/svg+xml", purpose: "any")
  3. Update `frontend/public/sw.js`:
     - Ensure `SHELL_ASSETS` includes the generated core icons (`/favicon.ico`, `/favicon.svg`, `/icon-192.png`, `/icon-512.png`, `/apple-touch-icon.png`).
  4. Verify no obsolete or broken logo/icon paths exist across the project.

### Task 3: Production Build & Asset Verification
- **Steps:**
  1. Run `cd frontend && npm run build` (tsc -b && vite build).
  2. Verify all icons are emitted to `frontend/dist/`.
  3. Verify frontend test suite passes (`npm run test:run` or targeted checks).
  4. Inspect asset sizes and checksums.
