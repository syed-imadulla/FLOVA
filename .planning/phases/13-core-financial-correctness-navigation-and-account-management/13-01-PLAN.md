# Plan 13-01: Core Financial Correctness, Navigation and Account Management

## Objective
Fix existing core functional bugs across FLOVA:
1. Prevent voice transaction amount duplication on multi-transaction sentences.
2. Add income categories adapted to work profile.
3. Fix navigation & redirects (clean Activity screen, safe back navigation, central capture routes).
4. Implement complete logout flow that clears local state and prevents stale data exposure.
5. Increase application transaction and daily estimate limit to ₹10,00,000 (10 Lakh) from ₹1,00,000.

## Implementation Tasks

### Task 1: Fix Voice Transaction Amount Duplication
- **Files**:
  - `frontend/src/voice/extractTransaction.ts`
  - `backend/supabase/functions/process-voice/index.ts`
  - `frontend/src/services/voice.ts`
  - `frontend/src/screens/VoiceScreen.tsx`
  - `frontend/src/screens/AddScreen.tsx`
- **Actions**:
  - Split compound transcripts in `extractTransaction.ts` on conjunctions and clause boundaries (e.g., "and", "aur", "mattu", "mariyu", ",", ";").
  - Parse each clause independently to extract its own amount, category, type, and description.
  - Never reuse an amount across multiple transactions. If amount is missing in a clause, leave amount null and mark clarification required.
  - Populate both `transactions` array and `transaction` (first item for backwards compat) in `FinancialExtractionDTO`.
  - In `backend/supabase/functions/process-voice/index.ts`, update prompt to output `transactions` array and map each transaction into distinct candidate with stable UUID.
  - In `VoiceScreen.tsx` and `AddScreen.tsx`, handle multi-transaction utterances by passing `remainingCandidates` in `ReviewState` so user reviews each transaction sequentially on `/add`.

### Task 2: Add Income Categories & Profile Adaptation
- **Files**:
  - `frontend/src/app/categories.ts`
  - `frontend/src/app/TransactionForm.tsx`
  - `frontend/src/engine/candidateAdapter.ts`
- **Actions**:
  - Add canonical income categories: `salary`, `freelance`, `business_sales`, `delivery_earnings`, `service_income`, `commission`, `tips`, `other`.
  - Maintain compatibility with legacy category keys (`earnings`, `client_payment`, `platform_payout`, `sales`, `daily_wage`).
  - Provide `categoriesFor(type, workProfile)` that sorts / adapts income categories based on the user's `workProfile`.
  - Ensure uncertain transactions remain unclassified without auto-selection.

### Task 5: Centralize and Increase Daily Payment Limit to ₹10 Lakh
- **Files**:
  - `frontend/src/lib/limits.ts` (new file)
  - `frontend/src/profile/parseRupees.ts`
  - `frontend/src/profile/__tests__/parseRupees.test.ts`
  - `frontend/src/engine/candidateAdapter.ts`
  - `frontend/src/engine/validation.ts`
  - `frontend/src/services/data.ts`
- **Actions**:
  - Define `MAX_TRANSACTION_LIMIT_RUPEES = 1_000_000` and `MAX_TRANSACTION_LIMIT_PAISE = 100_000_000`.
  - Update `parseOptionalRupees` and `parseRequiredRupees` to use `MAX_TRANSACTION_LIMIT_PAISE`.
  - Enforce ₹10 Lakh boundary in `validation.ts` and `candidateAdapter.ts` and `data.ts`.
  - Disallow amounts > 100,000,000 paise across voice, receipt, and manual paths.
